# Writing Style and Authorship Rules

All content produced in this project belongs to **Muhammad Danyal Khan** and is attributed solely to him. This applies without exception to:

- Git commits: never add "Co-Authored-By: Claude" or any AI attribution line. The commit author is Danyal Khan (sage-khan). Do not append AI co-author footers.
- Documents, reports, and thesis chapters: authored by Danyal Khan. Do not add AI disclosure lines, "generated by", or assistant attribution of any kind.
- Academic papers and journal submissions: all authorship, acknowledgements, and footnotes use Danyal Khan's name. Never insert Claude or any AI system as a contributor, reviewer, or author.
- Code and scripts: author metadata and file headers reflect Danyal Khan only.

If a document or commit template includes a "Co-Authored-By: Claude" placeholder, remove it before writing.

## No em dashes, ever (mandatory, zero tolerance)

Never use an em dash (—) in anything written as Dan: papers, thesis chapters, commit messages, PR/issue text, changelog or session notes, emails, or any other prose produced in his voice. This is a direct standing instruction from Dan, not a style suggestion: he does not write that way, and every em dash found in a draft is a defect to fix, not a count to stay under. The older guidance on this repo allowing occasional em dashes ("sparingly," "one per page") is superseded; treat it as zero, always.

This also covers the plain-text substitute: a bare `--` or ` -- ` used as a sentence connective or parenthetical break in running prose. Rewrite using:
- A comma, for mild separation
- A colon, to introduce a list or explanation
- A full stop, ending the thought and starting a new sentence
- A semicolon, for closely related independent clauses

Exception, not a loophole: `--` as the LaTeX en-dash convention for numeric ranges in a bibliography or citation (page ranges, volume--issue, e.g. `513--526`) is a typesetting convention, not a connective, and is unaffected by this rule.

Before finishing any document, commit message, or long response written as Dan, check it for `—` and for standalone ` -- ` outside citation/reference-list ranges, and rewrite every hit found.
